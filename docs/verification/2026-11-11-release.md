## Run form

Git and gitleaks are not installed on Windows, so the history checks ran in the pinned gitleaks image (`ghcr.io/gitleaks/gitleaks:v8.30.1`, which has `git`) with the repository mounted read-only. Git Bash rewrites a standalone `/repo` argument to `C:/Program Files/Git/repo`, so the mount stays `:/repo:ro` and the path arguments are written `//repo`. Each git command was run alone, with the output read from the saved output file because pipes are not allowed (the `awk` and `grep` filters of the audit table were replaced by searches of that output).

The git prefix used below, called `GIT` in this file:

```bash

```

| Package (installed) | Advisory | Reaches |
| --- | --- | --- |
| `js-yaml` 4.2.0 | GHSA-52cp-r559-cp3m, GHSA-5p4m-2wfm-xmqj, GHSA-2883-xcg3-v3hh (high, CPU use from crafted YAML). Fixed in 4.3.2 | `@hey-api/openapi-ts` 0.99.0, through `@hey-api/json-schema-ref-parser` and `@hey-api/shared` (4 high) |
| `minimatch` 10.2.6 | GHSA-g3hv-75wg-m249 (moderate, CPU use from crafted glob patterns). Fixed in 11.0.1 | `eslint` 10.14.0, `@eslint/config-array`, `@eslint/js` and `typescript-eslint` 8.72.1 with its `@typescript-eslint/*` packages (10 moderate) |

Why they are not fixed: `npm audit fix --force`, the only fix npm offers, installs `@hey-api/openapi-ts` 0.97.0 and `eslint` 9.39.5, which are older majors than the pinned ones. `js-yaml` 4.3.2 exists (`npm view js-yaml dist-tags`: `v4-legacy` 4.3.2), and `minimatch` 11.0.8 is the latest. A lock-only update of `js-yaml` would clear 4 of the 14. I tried `npm update js-yaml --prefix frontend`, and the shell refused it, so the lock is unchanged. A `minimatch` fix needs an `overrides` entry for a major version that ESLint 10 does not declare, and it would need a `lint` run to confirm.

Exposure: the tools run at build and lint time on the repository's own files (the OpenAPI document and glob patterns written by the project). They are not in the frontend bundle or the nginx image.

**Owner's decision: pending.** Options: update the `js-yaml` lock entry now, add a `minimatch` override and run `lint`, or wait for upstream releases of `@hey-api/openapi-ts` and ESLint that carry the fixes.
