# VRAM tuning procedure on the reference machine, 2026-11-25

Status: recorded 2026-11-25 for P02.7. The [measuring and tuning procedure](../gpu-orchestration.md#measuring-and-tuning),
version 2, ran again for `rocinante-x-12b`, the default text profile on both tiers since
[ADR 0045](../decisions/0045-drop-gemma-4-rocinante-x-default.md). Every trial of the plan was measured in this task,
every decision was computed by `Get-GpuTuningDecision`, and T-GPU-14 passes. `rocinante-12b-v1.1` has the same
architecture and reuses the result, as the procedure states. The catalog's `vram_preferred_mib` of both profiles now
comes from the measured peak.

## Decisions

Computed by `Get-GpuTuningDecision` from `tuning-20261125-221523.json`; none was set by hand.

| Step | Decision | Reason from the results file |
| --- | --- | --- |
| 3, 4, level | A | The margin at level A is 2224 MiB, at least 512 MiB |
| 5, context | 16384 allowed | 2224 MiB at 12288 and 1580 MiB at 16384, both at least 1024 MiB |
| 6, batch | 512 | Prompt speed against 2749 T/s: 256 -3.1 %, 1024 +4.4 %, 2048 +1.6 %; none gains 20 % |
| 7, `MOE_CPU_LAYERS` | 0 | Not a mixture-of-experts profile |
| 8, `USE_MMAP` | 0 | `USE_MMAP=1` saves 337.8 MiB of RAM (under 2 GiB) and -0.3 % of the reload time (under 20 %), at -0.4 % of speed |
| 9, `KV_QUANT` | `f16` | `q8_0` frees 892 MiB at its peak but costs 6.0 % of speed (over 5 %), and the context already grows with `f16` |
| T-GPU-14 | Passes | Median 53.1 tokens per second over 20 replies of at least 200 tokens (at least 15), first token of a 6087-token prompt in 2.22 s (at most 20 s), at level A, which keeps the margin rule |

The MoE comparison of step 7 (AutoFit against `MOE_CPU_LAYERS` 8, 12 and 16) is not applicable: ADR 0045 removed the
only mixture-of-experts profiles, and both catalog profiles are dense. The SWA padding measurement of P04 applies only
to the `gemma4` family and is not applicable either.

Every decision equals the one of the DROP.1 run earlier the same day; the numbers differ by at most a few MiB and a
few tenths of a percent, except the RAM saving of `USE_MMAP=1` (337.8 MiB here, 370.1 MiB then).

## Catalog values

The catalog's launch values already were the decisions above (level A, context 12288, batch 512, `MOE_CPU_LAYERS=0`,
`USE_MMAP=0`, `KV_QUANT=f16`), so `config/model-catalog.json` keeps them. Step 5 allows 16384, and the catalog stays
at 12288: that is the owner's decision recorded as an open question in ADR 0045, and this task does not change it.

VRAM values, by the rule "measured peak plus 5 %" of
[Verifying GPU release](../gpu-orchestration.md#verifying-gpu-release):

| Profile | Measured footprint at level A | Source | Plus 5 %, rounded up | `vram_preferred_mib` | `vram_required_mib` |
| --- | --- | --- | --- | --- | --- |
| `rocinante-x-12b` | 10058 - 841 = 9217 MiB | trial A, this task | 9678 MiB | 9000 -> 9678 | 6000, unchanged |
| `rocinante-12b-v1.1` | 10072 - 859 = 9213 MiB | T-GPU-02, `text-profiles-20261125-214343.json` (DROP.1) | 9674 MiB | 9000 -> 9678, the value of the profile it reuses | 6000, unchanged |

The measured peak is the footprint with every layer on the GPU, which is what `vram_preferred_mib` describes: below
it, autofit keeps fewer weights on the GPU. `vram_required_mib` is the free memory below which a load is held back;
set to the same peak, it would turn autofit's partial offload, and launch levels B and C, into a refusal. No load with
fewer layers on the GPU was measured, so the hard requirement keeps its planning value 6000, which is also the value
`VramRequirements` of the orchestrator uses. Whether the hard requirement should be the full peak is left to the owner.

## Default rule

Rule 1 of [Defaults and how they can change](../models.md#defaults-and-how-they-can-change) is applied: the default
`rocinante-x-12b` meets the speed rule at its catalog values, and it is dense, so the fallback for a
mixture-of-experts default does not apply. It stays the default on both tiers. Rules 2 and 3 need the P04 protocols
with the owner's ratings, and rule 4 the P05 image grid; none of them ran here.
