## What failed and what changed

No product code changed in this task. All four fixes are in tests, written in earlier tasks, that had not run against the whole project before this exit.

- **`integration`, backend `test_ai_resources.py`:** the test enqueued an `image_request` and expected it under `by_mode.image`. A new `image_request` starts in its `prompt` stage, which needs the text model, so the snapshot correctly counted it under `llm` (2 instead of 1). The test now enqueues the job at its `render` stage.
- **`e2e`, `models.spec.mjs`:** `getByLabel('File')` matched "Tipo di file" as well as "File", and Playwright's strict mode refused it. The spec now passes `{ exact: true }`, in both places.
- **`e2e`, `chat-list.spec.mjs`:** `openCharacterForm` decided whether to click "Nuovo personaggio" with one `isVisible()` look after "Annulla" appeared. The dialog paints the picker once before its loading note, so the look could land on the loading frame, skip the click and leave the picker open. The helper now clicks again until the name field shows, inside `toPass`. It failed in one of three full runs and passed in the other two, so it was a race; the last run passed with the new helper, and a single pass does not show that the race is gone.
- **`docker`, `Data.Tests.ps1`:** the backup tests expected 2 files, the database and one media file. Since P06.6a the backend writes `runtime/llm-launch.env` at startup, and a backup holds `runtime/`, so a backup now holds 3. The three counts (backup, restore-check, restore) are now 3.
