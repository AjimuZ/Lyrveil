### The fixtures and the round trip

- The fixtures are `backend/tests/fixtures/tavern_cards/v1.json`, `v2.json` and `v3.json`, synthetic and written for Lyrveil. They are JSON files: the V2 PNG is built from `v2.json` inside the tests (`card_png` in `test_card_imports.py`, and the `chara` and `ccv3` chunk writers in `test_tavern_card.py`), so no PNG fixture file is stored. `test_card_imports.py` imports `v2.json` as JSON and as PNG and `v3.json` as JSON, and `GET .../source` returns the stored card equal to the fixture.
- Lyrveil to a V3 PNG to Lyrveil gives an equal card (`test_lyrveil_to_v3_png_to_lyrveil_gives_an_equal_card`). A card, then Lyrveil, then a card keeps every unknown field (`test_card_export.py`). A card edited elsewhere names its changed fields, and a tampered embedded card is refused (`test_card_roundtrip.py`). All passed in the `integration` run.

## What failed and what changed

The specs of P10.6 and the P10.1 parser had not run together with the full levels before this task. Three failures came up and were fixed; one change is in product code (`card-actions.scss`) and two are in test code.

- **`unit`, backend: `test_import_rules.py::test_the_package_follows_the_import_rules`.** `lyrveil.domain.tavern_card` imports `lyrveil.consistency.content_guard`, which the rule "domain imports no other layer" refused. The parser must guard every string it reads (ADR 0037), and the guard is pure text rules over domain types, so the rule now allows that one module for the domain layer, with a comment, a sentence in `docs/backend.md` (Quality gates), and two cases in the test: the guard is allowed, and another `consistency` module is still reported. The alternative, moving the guard into `domain`, touches every importer and its tests and was not done.
- **`unit`, frontend: `app.routes.spec.ts`.** The list of documented routes lacked `characters/import/:importId`, which P10.6 added to the table of `docs/frontend.md` (Routes) and to the route table. The spec now lists it.
- **`e2e`: `responsive.spec.mjs` at 320 px and at 200 % zoom of 640 px, on `/characters/new`: "the screen area scrolls sideways".** The file input of the new import control is as wide as its "no file chosen" text and pushed the screen sideways. `card-actions.scss` now sets `min-width: 0` and `max-width: 100%` on the control. The first `e2e` run had 110 passed and these 2 failed; the second run passed all 112.

The new unit specs and `card-import.spec.mjs` passed on their first run. No test was disabled, skipped or deleted.
