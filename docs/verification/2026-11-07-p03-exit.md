## What failed and what changed

No product code changed behavior. Every failure was in a test that no run had checked before, except one markup defect that an accessibility check found.

- **`unit`, frontend:** `character-profile-screen.spec.ts` left the avatar list request `GET /api/v1/characters/c1/assets?kind=avatar` open, so `verify()` failed and the next tests failed with it. The spec now answers that request in `beforeEach`.
- **`e2e`, T-CHR-04 and T-CHR-08:** axe reported `aria-allowed-role` because the purge confirmation was a `<form role="alertdialog">`. The `alertdialog` is now a `<div>` that holds the `<form>` (`character-profile-screen.html`). This is the one change to shipped markup. It changes no text, behavior or layout.
- **`e2e`, T-CHR-11:** `getByText('Principale')` also matched longer texts, and the stored primary choice was read before the click was saved. The spec now matches the exact text and polls the API.
- **`e2e`, T-CHR-13:** `getByLabel('Interesse 1')`, `'Espressione 1'` and `'Frase da evitare 1'` also matched the remove buttons (`Rimuovi interesse 1`), so they are exact now. The outfit key message shows only after the field is touched, by design, so the spec leaves the field first.
- **`e2e`, scenarios:** after a chat is started from a scenario, a character has two chats. `openChat` in `tests/e2e/support/chats.mjs` now opens the first row, the most recent one.
- **`docker`, T-DCK-12:** three defects in `Data.Tests.ps1`. `Get-WrittenBackup` read `$Matches` after `Should -Match`, which does not set it in that scope, so the backup name was empty and three restore tests failed with it. The image `lyrveil/backend:data-test` came from before Pillow was a dependency, and setup builds an image only when it is missing, so `round_trip.py` could not import `PIL`; the test now builds the backend image first (the layer cache makes an unchanged build fast). `Invoke-RoundTrip` failed on the empty output of `seed`, and now also reports standard error in its failure message.
