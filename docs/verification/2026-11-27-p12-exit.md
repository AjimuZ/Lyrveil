## What failed and what changed

Three things failed on the first run of the levels, and none was a test left disabled:

1. **`unit`, frontend build of the specs.** `keyword-test.spec.ts` did not compile under `ng test`: `entries[0]` is possibly undefined (TS2532, 5 places). The spec now reads the entries with `?.`. `test lint` had not caught it because it does not type-check specs.
2. **`unit`, `lore.model.spec.ts`.** `bookFieldOf('Il nome non può essere vuoto.')` returned null. The server words the empty-name refusal without «», so the book form would have shown that error on no field. `bookFieldOf` in `lore.model.ts` now recognizes that sentence and places it on **Nome**. This is a defect in the product code that the spec found.
3. **`e2e`, `personas.spec.mjs` (T-PSN-06, passed in the P11 exit).** The first run failed on the first try of the note field. Two causes were in the spec: its helper clicked **Dettagli** after checking the panel before the conversation had loaded, which could close a panel that was already open, and it asserted that the context panel has no combobox, which is no longer true since the panel holds the world-link picker (P12.5b). The helper now waits for the button and reads its `aria-expanded`, and the assertion is that the panel has no **Persona** control. Behavior is unchanged; the panel itself was not modified. The second `e2e` run passed in full, T-LOR-07 included.

The order of the runs was: `unit` (failed twice, one fix each), `unit` (passed), `integration` (passed), `e2e` (failed once), `e2e` (passed after the spec fix), `unit` again (passed, to read the Pester count), and `lint` last. `integration` ran once, before the `e2e` spec fix; no edit touched the backend, so it was not repeated.
