# Ralph Progress Log

## Codebase Patterns

- PowerShell scripts: ASCII only, Set-StrictMode -Version Latest, read text with Read-Utf8Text (explicit UTF-8), avoid New/Set/Remove/Start/Stop/Update verbs on private helpers unless SupportsShouldProcess is added, use $script: variables across Pester BeforeAll/It blocks to keep PSScriptAnalyzer clean.
- Never redirect native stderr (2>&1) while $ErrorActionPreference is Stop in Windows PowerShell 5.1; lower it locally first.
- Functions that return an exit code are cast with [int] by the caller, so stray pipeline output fails loudly instead of being read as a pass.
- Windows PowerShell 5.1: never assign arrays through an if expression ($x = if (...) { @() } else { @('a') }); an empty array becomes $null and a one-item array becomes a scalar, which breaks .Length under StrictMode. Assign a default, then overwrite in an if statement.
- A PowerShell entry point that forwards options to another tool must not declare parameters; read $args so tokens like -k or -v are not bound as PowerShell parameters.
- Native command output inside a PowerShell function that returns a status must be discarded ($null = & docker build -q ...) or sent to Out-Host, or it becomes part of the return value.
- Logging safety is enforced by an allowlist processor that runs last, not by a denylist: free text only in the constant `event`, identifiers as short tokens, numeric measures by suffix, exceptions without messages.
- Verify a capability by reading the effective state back (the journal mode SQLite reports, a probe table) instead of trusting that a setting was accepted.
- Report optional dependencies, such as the control API, in a separate field of the readiness report so they cannot turn the service not-ready.
- Keep each refusal reachable in a unit test through scripted capability answers, and also prove the real behaviour in an integration test on real files.
- Each Python component has <name>/Dockerfile with lock, lockfile, deps and test stages, and its own pyproject.toml with the same ruff, mypy and pytest settings. Add the name to $script:Components in scripts/lib/PythonComponents.psm1, and add a `!<name>/tests` exception to .dockerignore.
- Tests for a documented table restate the documented data in the test, so the test fails if the code and the docs drift apart. They then check every ordered pair, not only the legal edges.
- When ruff's naming rules conflict with a name fixed by the docs, use a targeted `# noqa: <code>` and put the reason on the line above.
- Prove that an allowlist is closed with three tests together: enumerate every request the single builder can produce and compare it with a set written out again in the test; show that the builder refuses everything else before a request exists; and use AST checks to show that the module has no other path to the network (pinned imports, one client, no shortcut functions).
- Structural source scans should flag the dangerous construct itself (for example the docker command alone or followed by a subcommand), not every message that names it, so ordinary error text does not trip them. Include negative cases for such messages.
- When two Python packages must enforce the same rule but share no code, copy the scanner into each test suite with a 'change both together' comment that names the other file, and make each copy assert that the folder it scans holds modules, so an empty scan cannot pass.
