# Ralph Progress Log

## Codebase Patterns

- PowerShell scripts: ASCII only, Set-StrictMode -Version Latest, read text with Read-Utf8Text (explicit UTF-8), avoid New/Set/Remove/Start/Stop/Update verbs on private helpers unless SupportsShouldProcess is added, use $script: variables across Pester BeforeAll/It blocks to keep PSScriptAnalyzer clean.
- Never redirect native stderr (2>&1) while $ErrorActionPreference is Stop in Windows PowerShell 5.1; lower it locally first.
- Functions that return an exit code are cast with [int] by the caller, so stray pipeline output fails loudly instead of being read as a pass.
- Windows PowerShell 5.1: never assign arrays through an if expression ($x = if (...) { @() } else { @('a') }); an empty array becomes $null and a one-item array becomes a scalar, which breaks .Length under StrictMode. Assign a default, then overwrite in an if statement.
- A PowerShell entry point that forwards options to another tool must not declare parameters; read $args so tokens like -k or -v are not bound as PowerShell parameters.
- Native command output inside a PowerShell function that returns a status must be discarded ($null = & docker build -q ...) or sent to Out-Host, or it becomes part of the return value.
- Logging safety is enforced by an allowlist processor that runs last, not by a denylist: free text only in the constant `event`, identifiers as short tokens, numeric measures by suffix, exceptions without messages.
- Verify a capability by reading the effective state back (the journal mode SQLite reports, a probe table) instead of trusting that a setting was accepted.
- Report optional dependencies, such as the control API, in a separate field of the readiness report so they cannot turn the service not-ready.
- Keep each refusal reachable in a unit test through scripted capability answers, and also prove the real behaviour in an integration test on real files.
- Each Python component has <name>/Dockerfile with lock, lockfile, deps and test stages, and its own pyproject.toml with the same ruff, mypy and pytest settings. Add the name to $script:Components in scripts/lib/PythonComponents.psm1, and add a `!<name>/tests` exception to .dockerignore.
- Tests for a documented table restate the documented data in the test, so the test fails if the code and the docs drift apart. They then check every ordered pair, not only the legal edges.
- When ruff's naming rules conflict with a name fixed by the docs, use a targeted `# noqa: <code>` and put the reason on the line above.
- Prove that an allowlist is closed with three tests together: enumerate every request the single builder can produce and compare it with a set written out again in the test; show that the builder refuses everything else before a request exists; and use AST checks to show that the module has no other path to the network (pinned imports, one client, no shortcut functions).
- Structural source scans should flag the dangerous construct itself (for example the docker command alone or followed by a subcommand), not every message that names it, so ordinary error text does not trip them. Include negative cases for such messages.
- When two Python packages must enforce the same rule but share no code, copy the scanner into each test suite with a 'change both together' comment that names the other file, and make each copy assert that the folder it scans holds modules, so an empty scan cannot pass.
- Put authentication in middleware before routing, not in per-route dependencies. Then routes that don't exist and routes added later are covered too, and a 401 never reveals which routes exist.
- When a direct dependency drifts a shared transitive package away from the version in docs/technology.md, pin it with `[tool.uv] constraint-dependencies` instead of adding it as a dependency.
- Test constant-time token comparison by replacing `hmac.compare_digest` with a spy through the `hmac` module, and assert that every refusal went through it.
- Prove a lint rule with fixture files kept in the config's `ignores`. A `node --test` file lints them through the ESLint API with `ignore: false`, using the project's real config, and asserts the exact reported lines.
- In nginx, put security headers once at server level with `always`, and set caching with `expires` instead of `add_header`. A location's own `add_header` would stop it inheriting the server-level headers.
- Write tool scripts as ES modules that export pure functions for unit tests and run their CLI part only when `import.meta.url` equals `pathToFileURL(process.argv[1]).href`.
- A generated artifact that is committed gets two gates: a producer-side test comparing it with the live source, and a consumer-side lint that regenerates into a temporary folder and diffs it (line ends normalized).
- Browser APIs that tests must script, such as WebSocket, go behind an InjectionToken factory with a minimal structural interface. Tests then provide a fake and drive time with Vitest fake timers.
- Pass third-party generator configuration from code in a tool script shared by the generate and check commands. Do not rely on a config file the tool discovers on its own.
- When a Dockerfile's last stage is a test stage, name the runtime stage explicitly with `target:` in Compose.
- Use `env_file` with `required: false` where a missing `.env` should be reported by the app's own start-up check.
- Ruff SIM113 flags a manual counter in a `for` loop; use `enumerate` and let the loop index carry the count.
- Keep docstring lines at 120 characters or fewer; ruff E501 covers docstrings in test fakes too.
- A test level that starts containers should clear any earlier project first, run in try/finally, always remove containers, networks and volumes, and then verify by label that nothing is left. A removal that cannot be verified counts as a failure.
- Name the Compose project with `-p` on every command of a test level, so an environment variable cannot point cleanup at a real installation.
- Invoke external tools by bare name (`docker`, `npx.cmd`) rather than `docker.exe` so Pester stand-ins first on PATH can intercept them.
- Windows PowerShell 5.1 drops double quotes inside native arguments: use Go templates without quotes, such as {{json .Labels}} or {{.Names}}, never {{index .Labels "x"}} or {{.Label "x"}}.
- Wrap single-line native output in @() before indexing: a function returning @($output) with one line gives back a string, and [0] is its first character.
- Call %SystemRoot%\System32\tar.exe explicitly: from Git Bash, tar is GNU tar and reads C:\ paths as a remote host.
- PowerShell variable names ignore case: inside a Pester -ForEach case, a local $row overwrites the case data $Row.
- When capturing native stderr with 2>&1, set $ErrorActionPreference = 'Continue' locally so PS 5.1 error records never throw under 'Stop'.
- Capture Write-Host output of a function in tests with `6>&1` and separate the returned [int] from the InformationRecords.
- Mandatory PowerShell parameters that take a collection which may be empty need [AllowEmptyCollection()].
- Keep .ps1/.psm1 files ASCII for Windows PowerShell 5.1: build non-ASCII output such as 'è' with [char]0x00E8.
- Lifecycle commands return an [int] exit status and print only with Write-Host or Out-Host, so lyrveil.ps1 can `exit ([int]$status)` and tests can capture text with 6>&1.
- Test helpers in tests/docker must avoid the verbs New/Remove/Set without ShouldProcess, because PSScriptAnalyzer runs on test files too.
- Code that runs in the only container with a route out imports the standard library only, enforced by a unit test that compares its imports to sys.stdlib_module_names.
- Docker test projects that need network fixtures share generated data (catalog, CA) through a project-owned volume and gate on it with a health check, so nothing reaches the Internet or an installation's volumes.
- Native tools whose exit status is part of the contract avoid argparse's exit 2 by overriding ArgumentParser.error, because 2 is reserved for preflight failures.
- One-off maintenance containers use Get-ToolContainerArgument in scripts/lib/DataFiles.psm1: docker run --rm --pull never --network none --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges:true --user 10001:10001, with --mount (not --volume) so Windows sources such as C:\ stay unambiguous; refuse folders with commas or double quotes.
- Write files that must appear whole under a temporary name, then hard-link (no-clobber) or rename into place, and verify the result (hash or check) before giving it its final name.
- Python code under backend/src must not contain the docker command text (the socket scan in test_docker_socket.py flags it); keep container invocations in the PowerShell scripts.
- In PowerShell 5.1 test code, avoid the verb New- for helpers (PSUseShouldProcessForStateChangingFunctions); Write-/Get-/Invoke-/Export- are safe.
- When nginx and the backend both set a response header, hide the upstream copy with proxy_hide_header: repeated COOP or CORP values stop parsing and browsers ignore them.
- Starlette exception handlers for Exception run outside the user middleware stack, so they must set security headers themselves.
- Log refusals with a constant event name and error_code only, never the refused Host or Origin value.
- Prove that a container has no way out without needing the Internet: check that /proc/net/route and /proc/net/ipv6_route (ignoring lo) have no default route, and use a container on a bridge network as the positive control.
- Pass Python one-liners to docker from Windows PowerShell with single quotes only inside the code, so the native argument is not mangled.
- Resolve compose.yaml with `--env-file <empty file in TestDrive>` and with the interpolated variables removed from the process environment, so a test judges the file's defaults and never reads a real .env.
- Each CI job runs the commands of the matching local level. A job that cannot call scripts\lyrveil.cmd (Windows-only) calls an exported function of the same module instead.
- Third-party release binaries fetched in CI are checked against the release's checksum file before use.
- Prove a capability in the real image with an exec case in the Pester lifecycle test that queries the app's own readiness route, not only with in-process tests.
- Run `scripts/lyrveil.cmd test <level>` piped to grep on the summary lines to get result counts without the full output.
- Declare expected-hash and expected-size build ARGs after the download RUN, so mismatch tests reuse the cached download and still run the check.
- For container tests from Windows PowerShell, pass file content as base64 to `bash -c` with a script that has no double quotes, and use tmpfs mounts in place of read-only volumes, so no bind mount is needed.
- Entrypoints that validate config can offer a --print-command mode that runs every check and prints the argv, so the command logic is testable with no GPU or model.
- Strict, frozen, extra=forbid Pydantic models for config files. `parse_catalog` turns the ValidationError into one CatalogError that lists every problem with its field location.
- A test that parses a documentation table and compares it with a shipped data file keeps the docs and the data from drifting. Copy the page into the test stage and use `.dockerignore` negations, as docs/runtime-contracts.md already does.
- Mutate shared asyncio state only from synchronous methods that never await. Before each await in a long operation, enter a state that refuses concurrent requests (LOADING or UNLOADING) so those requests see consistent state.
- Map port errors (gate, NVML) to the documented error codes at the adapter boundary (SupervisorError.code), so callers report `last_error` without parsing messages.
- Mypy strict flags a repeated `assert obj.prop is X` after a mutation as non-overlapping. Compare a tuple such as `(obj.state, obj.lease) == (...)` instead.
- Adapters list every path they call in a module-level ENDPOINTS constant, and a unit test parses the docs/runtime-contracts.md tables and fails on any '/api/' string constant in the module that the contract does not list.
- Bound streaming reads with anyio.fail_after around each `anext()` call, never around a `yield`, so one wait can tell a stall from the total deadline.
- Pure renderers that feed the KoboldCpp prompt cache return the full text plus the prefix that stays stable, so tests can check byte-for-byte prefix reuse without a model.
- Neutralize untrusted text at the single point where control markers are written, so only that code can produce real markers.
- Repositories take a caller-owned SQLAlchemy Connection and never commit, so domain changes and the jobs they create share one transaction.
- Store timestamps with lyrveil.domain.identifiers.to_utc_text (UTC, milliseconds, Z) so text comparison in SQL follows time order. Primary keys use new_id() (UUIDv7).
- ruff's N818 rule requires the Error suffix on exception names, and UP047 requires PEP 695 type parameters (def f[T](...)) instead of TypeVar.
- In tests, use a typed inner function with a Connection parameter instead of a lambda when calling write(engine, fn).
- Save first, then queue: commit the user's data in its own transaction and queue the job in a second one. A failure to queue marks the placeholder failed instead of rolling back the user's text, and a retry under the same idempotency key finishes the work.
- For any retryable action, derive the job's `idempotency_key` from a stable id (`chat_reply:<message id>`), and have the retry path check whether the job exists before resetting a failed placeholder.
- Services raise DomainError subclasses (NotFoundError, ConflictError, ValidationFailedError, PayloadTooLargeError). The API maps them to problem+json through the shared handler, so routers hold no error logic.
- A job handler that owns domain state settles it on failure itself, using the queue's retry rule (retryable and job.attempt < job.max_attempts), inside `anyio.CancelScope(shield=True)`, then re-raises so the scheduler stores the job outcome.
- Test WebSocket streams with raw ASGI messages on the test's own event loop and `anyio.fail_after`, not Starlette's blocking test session, so a missing frame fails instead of hanging.
- Keep one shared dict builder for public documents, such as `message_document`, and have REST models validate from it (`Model.model_validate(...)`), so REST and events never disagree on shape.
- Turn user text into FTS5 queries by extracting \w+ words and double-quoting each one. Never pass raw user text to MATCH.
- Keep FTS tables in step with their source rows through SQL triggers in the same transaction while no application-side transformation (such as stemming) is needed.
- A list screen keeps its state in a root-provided store of readonly signals. Actions call REST and then reload, and a reload overtaken by a newer one is dropped by a ticket counter.
- Open a modal with a native <dialog> element and showModal(), which gives Esc, focus trapping and focus return for free. Row menus are disclosure buttons (aria-expanded, plain buttons), not role=menu, so no arrow-key behavior is implied. Close them with a host binding on document:keydown.escape, because the template lint rejects key handlers on non-focusable elements.

- A migration that must populate a new table from existing rows builds the data in SQL, using SQLite JSON functions such as json_object and json_group_array. It does not import application code, which will change after the migration is written.
- An append-only table gets a BEFORE UPDATE trigger that raises ABORT, plus a test that proves the update is refused. Foreign keys with RESTRICT already protect against deletes.
- Services compare the validated new value with the stored one inside the write transaction and skip the write when they are equal. That is how a 'save with no change' creates no version.
- Validation rules live as pure functions returning a catalog key plus params, mirroring the backend rules. The form schema, unit tests and any other caller share them.

- Derived search text (stems) is written by application code in the same transaction as the source row, through a persistence helper, not by SQL triggers.

- A job that stores model output writes its run row in a short transaction before generation. The commit transaction then reads the inputs again (cursor, input hash) and marks the run superseded instead of writing when they changed, so slow generation never commits against stale data.
- Model output that cites inputs by label (E1, P1, message seq) is resolved against maps built when the prompt was made; an unknown label drops only that item and increments a counter, and never refuses the whole output.
- Integration tests of model-backed jobs can use a scripted in-process TextRuntime (generate returns queued texts and records each TextRequest) with the real JobScheduler and a fake clock shared with JobQueue to step through backoffs.
- Keep model-output policy as a pure decision function (inputs: resolved item plus the existing rows it may touch; output: a frozen Decision) and let a thin service read the inputs and write the decision in the caller's transaction; unit-test the rules without a database.
- Every automated change to a memory row goes through a revise-then-update helper that snapshots the whole row into memory_revisions under its current version and bumps version, in the same transaction.
- Phrase lists per language live in prompts/<code>/<name>.txt and load with lyrveil.memory.window.phrase_patterns(language, file_name); match with is_significant.
- Write the tombstone before deleting the row, in the same transaction, so no deletion leaves nothing behind.
- Keep the pure decision (`is_blocked`) separate from the SQL that reads the tombstones, so unit tests cover the rule and integration tests cover the wiring.
- With SQLAlchemy text() and an IN list, keep the SQL in a module constant and write `text(SQL).bindparams(bindparam('name', expanding=True))`. This also avoids ruff-format ambiguity around chained calls.
- For scope isolation, check the conversation's own opt-in in SQL (EXISTS on conversations.shares_memory) as well as the caller's flag, so a wrong flag alone cannot leak data.
- When a SQL string would land near 120 columns, run lint: ruff format may join implicit string concatenations that fit.
- Make an append-only record immutable with a SQLite `BEFORE UPDATE OF <all columns except status>` trigger that raises ABORT, so a later version needs a new row.
- In a background job, re-read what the job covered inside the commit transaction and compare its hash. If the data changed during generation, write nothing, report `superseded` and re-check the trigger.
- Keep selection, chunking and rollup rules in a pure `memory/*.py` module that takes plain dataclasses, and keep the SQL in `persistence/*.py`. The rules can then be unit-tested without a database.
- Price per-family template overhead with a fixed probe: count two constant prompts that differ by known turns. The counter cache keeps the result per model, so it costs nothing after the first reply.
- Log fields must end in `_tokens` or `_count`, or be allowlisted identifiers. Log booleans as `<name>_count=int(flag)`; free text and string lists are dropped by `keep_allowed_fields`.
- To make a budget test deterministic, derive the squeezed window from a first build's `token_total`, and don't guess window sizes.
- Compute derived state only as a pure fold over the history rows, and rewrite the stored row from a fold of the rows read back after every change. Then the stored value equals a replay of the history by construction, and invalidating a row needs no special case.
- Rows from one run share their `created_at`; order such rows by `created_at, rowid`, because UUIDv7 ids made in the same millisecond have no defined order.
- Inside test loops, Ruff B023 flags lambdas that capture loop variables even when they are called at once. Move the call into a module-level helper that takes the values as parameters.
- Run derived-data invalidation in the caller's write transaction of the user change, and queue only the model work, so the change and its invalidation commit together or not at all.
- When re-reading old input, guard against double counting and overriding newer state by checking what applied rows already cite and whether newer rows exist, instead of trusting the model.
- ruff format joins a signature or call onto one line when it fits in exactly 120 characters; count before wrapping, or let `test lint` report the diff.
- Write streaming text transforms as a chain of character-level stages whose decisions depend only on the characters seen so far; the output is then independent of chunking by construction, and a test can feed every split position.
- Write look-alike or invisible characters in Python source with \N{NAME} escapes, both for readability and to satisfy RUF001.
- For text matched with regexes but reported at positions in the original, fold one character into one character (NFKD(c.lower())[:1]). Indices then stay aligned between the folded and the original or masked text.
- Streaming filters stay chunk-independent when they process one character at a time, or hold back only the longest suffix that is a proper prefix of a marker. Test this by splitting fixed inputs at every chunk size.
- Derive per-chat rolling state (like the adaptive notes) from what is already stored on earlier rows, not from in-memory dicts. It then survives restarts, and regenerating a reply reproduces the same inputs.
- Studio-style read services return plain dicts shaped for a pydantic response model; the router wraps them with Model(**dict), and each read names its owner (a character or a conversation) so data never mixes across chats.
- Frontend feature stores use a ticket per read (stale responses are dropped), keep the previous rows on a failed read and set a part-level error, and run every action as act(): call the API, read the list again, refresh any open detail.
- For repeated controls in Angular templates (cards), put `data-testid` on the card and scope e2e locators and unit queries to it; the unit specs use the fixture.whenStable + setTimeout `settle()` loop before and after flushing requests.
- To test a flow that spans the reply handler and the API, reuse `FakeRuntime`, `new_chat`, `worker_for` and `Ticks` from `integration.test_reply_streaming`, send with `MessageService(engine).send`, and run the job with `scheduler.run_once()`. A `TestClient` without a context manager does not run the app's worker.
- Anything written as a side effect of a reply goes in its own short transaction after the reply is stored, with a try/except that logs and continues, so it can never turn the reply into a failed job.
- Show stored memory text by reading it by id when it is displayed (nothing is copied into the diagnostic row), and say so in the UI when the row is gone.

## 2026-11-07T15:52:29Z - P04.7
- P04.7 is implemented. Editing, deleting, regenerating a message or switching its variant now updates what was derived from it, in the same transaction as the change. Re-evaluation then rebuilds what still holds.

**What happens on a message change** (`services/invalidation.py`, SQL in `persistence/invalidation.py`):
- **Memories.** A locked memory only gets `needs_review`: no revision, nothing else changes. A memory that still has another valid source loses the stale one and 0.1 of confidence, with a revision (`source_changed`). A memory with no source left becomes `invalidated` and keeps its sources.
- **Repairs (my own addition).** When a memory in use is invalidated, the last member left in its conflict group leaves the group. The fact it had superseded becomes active again, unless that would clash with a fingerprint or a single-valued subject already in use. So deleting "Ho cambiato lavoro… Verdi" brings "Studio Rossi" back.
- **Episodes** follow the same rule, without confidence. The state rows that cite the message are invalidated and the state is replayed.
- **Summaries.** Checkpoints covering the message are invalidated, and their level-0 range is queued to be summarized again.
- **Re-evaluation.** A `memory_reevaluation` job is queued for seq−6 to seq+6, cut to the extraction cursor. A regenerated reply queues its job once it is stored.

**Re-evaluation run** (`MemoryExtractionService`, now registered for this job kind):
- It reads the range without moving the cursor.
- An item with the fingerprint of an invalidated memory or episode brings that row back, with a revision (`reevaluation`) and the new sources.
- A relationship event already cited by a remaining state row is skipped. The mood/thread update is skipped when newer state exists.
- New age check in `decide`: an item older than the memory it would change is stored `superseded` instead. Without it, re-reading old messages would put newer facts in doubt.
- A window whose run completed before the job was queued is generated again. This is the one exception to "a completed run is never repeated".
